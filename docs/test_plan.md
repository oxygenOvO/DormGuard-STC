# 测试计划

| 编号 | 前置条件与操作 | 预期结果 |
| --- | --- | --- |
| T01 | 系统处于撤防状态，正常打开宿舍门 | 门状态更新，但不触发报警 |
| T02 | 关闭宿舍门后执行布防 | A 板成功进入 `ARMED` 并上报成功 |
| T03 | 门处于打开状态时尝试布防 | 系统提示门未关闭，A 板不进入 `ARMED` |
| T04 | 系统处于布防状态，打开门 | 触发 `MSG_DOOR_ALARM`，系统进入报警状态 |
| T05 | 系统处于布防状态，产生有效 Vib 事件 | 触发 `MSG_VIB_ALARM`，系统进入报警状态 |
| T06 | A 板处于布防状态，在 B 板执行撤防 | A 板退出布防状态并上报撤防成功 |
| T07 | PC 点击 ARM | `CMD_ARM` 成功经过 B 板到达 A 板 |
| T08 | A 板产生报警 | 报警经 B 板转发，PC 正确显示报警类型和状态 |
| T09 | A 板每秒发送 `MSG_HEARTBEAT` | B 板持续判定 A 板在线，并向 PC 显示在线 |
| T10 | 停止 A 板心跳并超过设定超时时间 | B 板和 PC 均显示 A 板离线 |

每项测试应记录固件版本、硬件连接、操作步骤、实测结果和异常现象。心跳超时时间、Vib 有效判定与 RESET 恢复策略在实现前由三人共同确认并更新相应设计文档。
